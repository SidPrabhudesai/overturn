From a photo of a letter to a draft appeal.

Accepts a PDF or a phone photo, plus an optional explanation of benefits to cross-check.

  1. Read

    A vision-capable model transcribes the document exactly as written.

  2. Extract

    It pulls the insurer, claim number, denial reason, code and deadline, each with a supporting quote.

  3. Check

    Code confirms every quote is really in the letter, using the PDF's own embedded text when it has any. A second model call confirms every stated right against an official source.

  4. Draft

    The letter is written from verified facts only, with a deadline countdown and a checklist of what to gather.

Built so it can be wrong safely.

The model is only allowed to make an answer more cautious, never less.

A fact needs its quote
If the quoted words aren't in the letter, or the quote doesn't contain the value, the fact is dropped and shown as "not found".
A right needs a source
Appeal rights are shown only if they cite a retrieved passage from an allowlisted government site, and a second check confirms the passage says so.
Hidden instructions are flagged
Obvious attempts to instruct the AI inside a document are flagged and discarded, and the drafting step never sees the raw document at all. This is a screen for common tricks, not a guarantee.
Dates are computed by code
The deadline countdown is ordinary date arithmetic on a verified date. The model never does the math.
Nothing is stored
Files are processed to answer the request. Message text is not logged.

Where this stands.

A working prototype, built for the Meta Global AI Developer Hackathon. It runs on Meta's Muse models. So far it has only been tried on synthetic letters, and the newest safeguards are still being measured.

No customers yet, no real patient data, no claims about outcomes. It is general information and not legal or medical advice.
